### Commands

```bash
export JAVA_HOME=$HOME/.jdks/jdk-21.0.12.1+1
PIXEL=<serial from adb devices>
check() { adb -s $PIXEL shell dumpsys activity activities | grep -m1 topResumedActivity | grep -q com.monostr.app || { echo "another app is in front"; exit 1; }; }

# build each: in a clean clone of the commit
cd android && ./gradlew --offline clean :app:assembleRelease --no-build-cache -Pmonostr.perf=true

# one cold start, switch off, BEFORE and AFTER, 4 runs each
adb -s $PIXEL shell am force-stop com.monostr.app
adb -s $PIXEL logcat -c
adb -s $PIXEL shell am start -W -n com.monostr.app/.MainActivity | grep TotalTime
sleep 20
adb -s $PIXEL logcat -d -s System.out | grep -E 'session ready|feed first notes|feed fresh page'

# 30 s feed scroll, one run per build
check
adb -s $PIXEL shell dumpsys gfxinfo com.monostr.app reset
# scroll with the finger or: adb shell input swipe in a loop for 30 s, after check
adb -s $PIXEL shell dumpsys gfxinfo com.monostr.app | grep -E 'Total frames|Janky|percentile|Slow UI'

# size of the app, switch off
adb -s $PIXEL shell dumpsys package com.monostr.app | grep -E 'versionName'
adb -s $PIXEL shell du -sh /data/app/*/com.monostr.app*   # may need the app's Storage screen instead
```

### Checklist for the user

Switch off, compare with 0.33.1, must be unchanged (spec 8), including compressed native libraries:

- [ ] 1. Cold start, `am start` TotalTime, session ready, feed first notes, feed fresh page: 4 runs each build. If cold start got worse: stop and decide (spec 7.5), do not choose alone.
- [ ] 2. 30 s feed scroll: frames, janky, p50 / p90 / p95 / p99.
- [ ] 3. APK size and installed size against the calculated 18.3 MB and about 31.9 MB (`docs/testing/tor-spike.md`).

Switch on, measured and reported, no target (real account, Settings, Connect through Tor):

- [ ] 4. Bootstrap, first and later: time from `Turn on` to the green onion. Fresh `Clear storage` for the first, force-stop for later; 3 runs of each. With the process killed only (`:tor` alive): 1 run.
- [ ] 5. With Tor connected: first notes, one picture, one send (the user's own test note or a like): stopwatch or the `System.out` marks of the perf build.
- [ ] 6. **Budget.** Background run with Tor: with the app closed and the phone idle. Use `adb -s $PIXEL shell dumpsys jobscheduler | grep -A3 com.monostr.app`, and `cmd jobscheduler run -f -n androidx.work.systemjobscheduler com.monostr.app <id>` (`-f` needs the job to be due; only on the user's word). From logcat `System.out`: `worker: N ms wall, process cpu M ms`. Worst bootstrap of 5 such runs, also after a night in Doze if the user can leave it, sets `TOR_BUDGET_MS`: bootstrap time + a margin. Keep 90 s if the worst is under about 60 s.
- [ ] 7. Real due run in Doze (not forced): leave the phone an hour or more; a DM sent from another account shows a notification without opening the app. This is the check the emulator cannot do.
- [ ] 8. `:tor` PSS on a release build while connected: `adb -s $PIXEL shell dumpsys meminfo com.monostr.app:tor | grep TOTAL`, 3 samples. Debug x86_64 gave 135 to 141 MB.
- [ ] 9. Battery: note `dumpsys batterystats --charged com.monostr.app` after a day with the switch on, if the user wants to spend the day.
- [ ] 10. Long-press on a link in a focused note shows no system Open action (plan step 6). Look only, no screenshot if the note is private. Done on the emulator as far as an emulator can; the Pixel's text selection toolbar is what counts.
- [ ] 11. With the real account: login row, feed, picture, tip sheet with the wallet note, and turning off. Spec 9 "Pixel with the real account".
- [ ] 12. Freezer: leave the app with Tor on, watch `:tor` for about 6 minutes (`adb -s $PIXEL shell pidof com.monostr.app:tor`). Is it gone at the end of the grace? A frozen main process runs no timer (Task 9 concern).
- [ ] 13. **The restart.** Direct session with the real account, Settings, Connect through Tor: the sentence `monostr restarts once.` shows; Turn on. The pid changes (`adb -s $PIXEL shell pidof com.monostr.app`, before and after), the app is back at Settings, no crash dialog, the green onion on the feed. Note the time from the tap to the end of the process (`ActivityManager: Process com.monostr.app (pid N) has died` in `adb -s $PIXEL logcat`, against the tap's `input` time or a stopwatch on a screen recording): that is the window after the flip in which old relay tasks still live, about 50 to 100 ms on the emulator, `docs/testing/tor-leak-test.md`.
